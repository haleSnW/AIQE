# 多 agent 测试分工与任务书模板（Multi-Agent Testing）

> 质量评估交给多个 agent 协作时，靠的不是「让 agent 自觉」，而是**明确
> 的角色边界 + 可验收的任务书**。本文档定义测试四角色分工模型、任务书
> 模板，并附带一个可直接复用的通用测试 agent skill（`skills/testing-agent/`）。
> 本模型取材自多智能体协作的常见实践（角色边界 + 可验收任务书），
> 表述已通用化。

---

## 1. 测试四角色分工模型

| 角色 | 职责 | 产出 | 边界（禁止） |
|---|---|---|---|
| **规划（Planner）** | 分解质量任务、维护进度、协调其他角色、审查交付 | 任务清单 + 每项任务的任务书 | 不直接写测试代码；不代替执行者下「已通过」结论 |
| **执行（Executor）** | 按任务书实现用例/脚本/修复，只做任务书边界内的事 | 代码 diff + 冒烟测试结果 | 不顺手重构；不改任务书范围外的文件；不跳过任务书里的验收命令 |
| **审查（Reviewer）** | 独立审查执行者的交付：对照任务书逐条核对 | 审查清单（通过/不通过 + 精确位置证据） | 不替执行者改代码；不凭印象下结论——每条结论带文件:行号 |
| **质量回溯（QA）** | 跑全量验收（语法/测试/接口一致性），输出通过/失败清单 | 验收报告（失败时含精确错误信息） | 不修复只报告；不在任务书外自行扩大测试范围 |

**协作铁律**：
- **角色分离**：执行者不审查自己的交付，规划者不裁决自己分派的任务——
  这是「测试能抓住测试者自己的错误」的前提。
- **任务书是契约**：没有任务书不派活；任务书里没有的验收命令，执行者
  不发明、审查者不要求。
- **质量回溯是最后一道门**：一批任务完成后必须由 QA 角色跑一次全量，
  通过/失败清单随批次归档。

## 2. 任务书模板

每项任务下发时附带一份任务书，字段全部必填（可精简为单行，但不可缺）：

```markdown
### 任务书 T-<编号>

- **任务**：一句话描述（做什么，不做什么）
- **来源**：需求/缺陷/计划中的哪一项（可追溯到上游）
- **边界（范围）**：
  - 只改哪些文件/目录（精确到路径）
  - 明确禁止：不重构、不引入新依赖、不改协议
- **验收命令**（执行者完成后必须逐条运行并回贴输出）：
  ```
  <命令1，预期输出>
  <命令2，预期输出>
  ```
- **超时提示**：本任务应在 <时长> 内完成；超过 <时长> 停止深入，
  回传部分结果与卡点，由规划者决定继续或降级
- **交付格式**：diff / 文件清单 / 报告路径
```

**验收命令的写法要求**：
1. 必须可复制粘贴执行，且写明**预期输出**（不是「应通过」，而是
   `91 passed` 这种可对照的文本）；
2. 必须能证明「任务真的完成了」——比如修复 bug 的任务，验收命令要
   包含「在 bug 还在的版本上先跑红、修复后跑绿」的完整序列（见 skill）；
3. 涉及真机/网络的验收命令默认 gated，注明「无环境时报告 NOT_ASSESSED」。

## 3. 任务书示例（可直接改参数使用）

```markdown
### 任务书 T-014

- **任务**：为 scoring 新增「响应含敏感信息」判定分支，输出 WARN 状态
- **来源**：process-management.md 五状态词汇（WARN 用例）
- **边界**：只改 src/AIQE/judge.py 与 tests/test_runner.py；
  禁止修改 protocol.py/schema.py，禁止引入新依赖
- **验收命令**：
  ```
  .venv/bin/python -m pytest tests/test_runner.py -q   # 预期: 新增用例全绿, 存量不回归
  .venv/bin/python -m pytest -q                        # 预期: 全绿 (基线 91 passed)
  grep -n "sensitive" src/AIQE/judge.py                # 预期: 命中新增分支行号
  ```
- **超时提示**：本任务 30 分钟内完成；超过 45 分钟停止，回传部分结果
  与卡点（含已试方案），由规划者决定降级
- **交付格式**：diff（str_replace 格式）+ 验收命令输出回贴
```

## 4. 通用测试 agent skill

配套的 `skills/testing-agent/SKILL.md` 是一份**可直接复用的 agent 指令**
（Claude Code 等支持 skill 目录的工具可直接加载）：把测试纪律——红→绿
验证、验收命令、禁止自证空转、边界声明——固化到执行角色每次开工前的
动作里，而不是依赖 agent 自觉。接入方式：

1. 把 `skills/testing-agent/` 目录复制到你项目的 `skills/` 下（或按你的
   工具约定注册 skill）；
2. 派「执行/审查」角色任务时，在任务书里注明
   「开工前加载 skills/testing-agent/SKILL.md」。

skill 的完整内容见 [skills/testing-agent/SKILL.md](../skills/testing-agent/SKILL.md)，
与本文档第 2、3 节配套使用：任务书定义「做什么」，skill 约束「怎么做」。
